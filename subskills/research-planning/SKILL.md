# 研究規劃與假說

## 呼叫方式與交接

由 [main_skill.md](../../main_skill.md) 選擇本模組，或依學生明確指定直接使用。先讀取 [共同原則](../../shared_rules.md)，再讀本次需要的內容。

- **輸入：** 研究題目、現有進度、研究目的、適用要求與已有資料。
- **輸出：** 研究資料卡、RQ／H 表、章節與證據對照表、待補項目。
- **回傳主流程：** 完成內容與檔案位置、使用的資料版本、學生確認狀態、待補項目與建議下一步。

需要學術圖時，將圖的目的、資料與尺寸交給 [學術圖製作](../../ieee-academic-figures/SKILL.md)，再接回本模組。一般比較表或工作表可在本模組完成。產生待修工作或實際修改時，將紀錄交給 [修訂管理](../revision-management/SKILL.md)。

學生剛開始或時間有限時，先依 [論文任務規劃](../thesis-task-planning/SKILL.md) 選出一項 60–90 分鐘的工作。已有任務卡時直接沿用。本模組依該任務整理問題卡、部分資料卡或一組 RQ／H，後續再逐步補齊研究規劃。

## 建立研究資料卡

以下是逐步累積的完整欄位。先讀取已有資訊；每次只收集當前任務用得到的部分，並在後續階段持續更新。題目與方法尚未確定時，先從一個具體情境及觀察到的問題開始。

| 欄位 | 可修改範例 |
|---|---|
| 系所與學位 | 國立中央大學○○學系碩士班 |
| 暫定題目 | 適用於校園服務的負載感知任務排程系統 |
| 撰寫語言與工具 | 中文正文、英文摘要；預設使用 Markdown（.md），依需要另匯出 Word 或 LaTeX |
| 應用場景 | 校園線上服務在選課期間出現集中請求 |
| 研究對象 | 接收並分派請求的任務排程服務 |
| 現有問題 | 固定輪詢未考慮工作節點的即時負載 |
| 提出方法 | 使用佇列長度與服務時間估計值選擇工作節點 |
| 現有資料 | 系統程式、匿名化請求紀錄與初步測試紀錄 |
| 現有進度 | 已完成原型，尚未執行正式比較實驗 |
| 時程 | 預計於○年○月完成實驗，○月口試 |
| 適用要求 | 系所範本、指導教授要求及預計投稿格式 |

資料足以說明研究方向時，依已確認的資料卡產出一段研究概要。每次只列出下一項任務最需要確認的資料，其餘保留在看板。

選題或調整範疇時，先檢查核心問題需要的資料、可用系統、比較方法與驗證條件能否取得。優先沿用可驗證的既有成果。先導測試可先確認一項關鍵可行性，再投入大規模實作。將必要研究範圍與可選延伸分開，交給任務規劃估計投入與期限；新增功能須說明它如何支持核心問題。

## 定義研究問題與研究假說

先區分四種內容：

- **研究目的：** 希望解決的問題。
- **研究問題（RQ）：** 本研究要回答的具體問題。
- **研究假說（H）：** 應用本研究提出的做法，能夠回答本研究問題的程度。
- **研究貢獻：** 方法、系統或證據帶來的新增知識與能力。

每項假說包含比較對象、測試條件、變數、主要指標與判定準則。說明預期方向或門檻的依據。將系統建置目標與研究假說分開列出。

可修改範例：

> **目的：** 降低高負載下的服務延遲。
>
> **RQ1：** 在相同運算資源與請求負載下，負載感知排程能否降低尾端延遲？
>
> **H1：** 在相同硬體與每秒 100 個請求的負載下，相較於輪詢排程，負載感知排程預期可降低至少 15% 的第 95 百分位回應時間。
>
> **保護指標：** 錯誤率增幅不超過事先設定的容許值。
>
> **待調整：** 請提供實際負載、改善門檻與錯誤率容許值，並說明其依據。

建立假說表：

| 項目 | 填寫內容 |
|---|---|
| 編號 | RQ1／H1 |
| 自變數 | 排程方法 |
| 依變數 | 第 95 百分位回應時間 |
| 控制條件 | 硬體、工作節點數、請求組合與資料版本 |
| 比較對象 | 輪詢排程 |
| 判定準則 | 改善幅度達指定門檻，並依預定分析方法評估不確定性 |
| 依據 | 使用需求、先導實驗或相關文獻 |
| 所需證據 | 原始測量、重複實驗、分析方法與結果圖表 |

需要統計推論時，再定義虛無假說 H₀、對立假說 Hₐ、分析單位、檢定方向與判定方法。使統計假說對應研究主張中的差異或門檻。

對以規格符合性或形式驗證為主的研究，列出待驗證命題與驗收準則，並說明與研究問題的關係。

### 檢查替代解釋

對核心假說列出合理的替代解釋。設計能區分兩種解釋的測試，並說明哪些結果會削弱原假說。

> **請提供：** 除了提出的方法，還有哪些因素可能造成改善？
>
> **可修改範例：** 延遲降低可能來自快取命中率增加。固定快取設定後，比較兩種排程方法；再關閉快取重測，以辨識排程與快取各自的影響。

在假說表中補上「替代解釋」「辨別實驗」與「不足以判定的情況」。依研究情境選用，不必為每項工程規格另建假說。

## 建立章節與證據對照表

建議章節為 Introduction、Related Work、System Design and Methodology、Experimental Design、Results、Discussion、Conclusion。依系所要求合併或拆分。

建立以下對照表，持續追蹤證據：

| 研究問題 | 假說 | 方法設計 | 驗證方式 | 結果位置 | 貢獻 |
|---|---|---|---|---|---|
| RQ1：能否降低尾端延遲？ | H1：達到指定改善幅度 | 負載感知排程 | 與輪詢進行相同負載比較 | 待補圖表與數據 | 待結果確認的效能證據 |

區分預期貢獻與已驗證貢獻。結果完成後，更新章節中的主張。

## 初次啟動範例

學生尚無題目時，沿用任務規劃已取得的情境與可用時間，先完成一份問題卡。每次交付一個可核對成果，後續再安排文獻與假說。

> **本次任務：** 用 60 分鐘整理一個熟悉的問題情境，記錄對象、具體現象、影響與待查證事項。
>
> **用途：** 具體化選題起點，供下一步查找資料與文獻。
>
> **可修改範例：**「校園線上服務在選課期間出現集中請求。使用者反映等待時間增加，目前尚缺延遲紀錄。下一步需確認系統能否匯出含時間戳記的請求資料。」
>
> **請交付：** 一份問題卡或口述逐字稿。尚未確認的資訊請標為待查證。

已有題目與原型時，直接接續目前缺少的成果。例如，本次只整理一組 RQ／H 工作表：
>
> **請提供：** 已有方法與比較對象，以及本次要評估的一個指標。
>
> **用途：** 在本次 75 分鐘任務中草擬一組假說的比較關係，列出尚缺的條件與判定依據。
>
> **可修改範例：**「本研究比較負載感知排程與輪詢排程，以 p95 延遲評估差異。實際負載、改善門檻與判定依據待補。」
